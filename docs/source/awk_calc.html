Calculate with AWK

On this page, you calculate with the growth data: you add a new column, and you calculate sums, counts and means, first for the whole table and then per group. You use the same folder as on the last page, with the data in awk_data/.

Calculations are where empty fields do the most damage, so keep the rule from AWK on a table in mind: skip empty fields with $4 != "" before you compare or calculate.

Add a column

AWK can calculate with fields. For example, the shoot weight per mm of root is $5 / $4. To add it as a new column at the end of each line, print the whole line $0 and then the result:

awk -F'\t' -v OFS='\t' 'NR > 1 { print $0, $5 / $4 }' awk_data/Growth_Data.txt > shoot_per_root.txt

wc -l shoot_per_root.txt

This prints:

awk: cmd. line:1: (FILENAME=awk_data/Growth_Data.txt FNR=123) fatal: division by zero attempted
121 shoot_per_root.txt

The error message tells you that AWK stopped at line 123: the first row with an empty root length. That is because it treated the empty field as 0, and a division by 0 is not possible. The file shoot_per_root.txt still exists, but it has only 121 lines instead of 594. If you missed the error message and only looked at head, the file would look fine. This is why you want to make it a habit to count lines after each step.

To fix this, you need to skip rows with an empty root length or shoot weight, and print a header for the new column. The command now has two parts, each with its own pattern and action.

A command with several parts gets long on one line. AWK lets you spread the part between the single quotes over several lines, so you can put each pattern and its action on a line of its own. The command does exactly the same, it is only easier to read. You can copy it into your terminal as it is: the terminal waits for the closing quote before it runs the command.

# Part 1: on line 1, print the current header and add a name for the new column
# Part 2: on the other lines with both values, print the line plus the result
awk -F'\t' -v OFS='\t' '
  NR == 1                          { print $0, "shoot_per_root" }
  NR > 1 && $4 != "" && $5 != ""   { print $0, $5 / $4 }
' awk_data/Growth_Data.txt > shoot_per_root.txt

# Check the result
head -3 shoot_per_root.txt
wc -l shoot_per_root.txt

This prints:

Nutrient    Condition   Experiment  Rootlength  FW_shoot_mg shoot_per_root
low_P   mock    ex61    40.4    6.6 0.163366
low_P   mock    ex61    38  6.8 0.178947

572 shoot_per_root.txt

572 lines: the header plus 571 plants. Does that add up? 594 plants, minus 15 without a root length, minus 8 without a shoot weight, is 571. No plant misses both values, so no row is subtracted twice.

ImportantKeep the opening brace on the same line as its pattern

When you spread a command over several lines, the opening { of an action must stay on the same line as its pattern. If you move the { to the next line, AWK reads the pattern on its own (which prints every matching line) and the action on its own (which runs on every line). You get no error, only a different result.

Sum and mean of a column: variables and END

You will notice that the commands on this page are longer than the ones on the last page. You could do the same thing in R or Python, and you might wonder why even learn them in AWK? The reason is that in bioinformatics you often only need a quick look at your data: what is the total number of reads I work with, how many plants are in each group, and do the means look sensible? AWK gives you that answer in the terminal, without starting another program or loading the table first. On a computer cluster, where R or Python may not be set up for you, AWK is always there. And because AWK reads a file one line at a time, it also works on files that are too large to open comfortably in R or Excel. For statistics and plots, R or Python remain the better tools. AWK is for the quick check before, or for cleaning up a table before you load it there.

Start with one number: the total shoot weight of all plants. For this, AWK needs a variable, a name that holds a value. You do not need to create it first: AWK makes the variable the first time you use it, and it starts at 0.

awk -F'\t' 'NR > 1 && $5 != "" { sum += $5 } END { print sum }' awk_data/Growth_Data.txt

This prints:

9715.23

Taken apart:

  • sum += $5: add the shoot weight of this line to the variable sum. += means “add to the value that is already in sum”.
  • END { print sum }: END is a special pattern. Its action runs once, after AWK has read the last line. By then, sum holds the total.

The name sum is your own choice. You could call it total or weight instead, and get the same result. Names such as NR, NF and END are different: they belong to AWK and have a fixed meaning.

For the mean, you need a second variable that counts the number of plants measured. Here it is called n (short for “number of plants”), and n++ adds 1 to it for each line AWK passed. The ; separates two steps inside one action:

awk -F'\t' '
  NR > 1 && $5 != "" { sum += $5; n++ }
  END                { print n, sum, sum / n }
' awk_data/Growth_Data.txt

This prints the number of plants, the total and the mean:

586 9715.23 16.5789

When you run such calculations, you want to check if 586 adds up: 594 plants, minus the 8 without a shoot weight, is 586.

Now leave out the rule for empty fields, and then also NR > 1 to see how slight differences in the code can make a difference:

# Without $5 != ""
awk -F'\t' '
  NR > 1 { sum += $5; n++ }
  END    { print n, sum, sum / n }
' awk_data/Growth_Data.txt

# Also without NR > 1
awk -F'\t' '
  { sum += $5; n++ }
  END { print n, sum, sum / n }
' awk_data/Growth_Data.txt

This prints:

594 9715.23 16.3556

595 9715.23 16.3281

The total is the same all three times. AWK adds an empty field as 0, and the header text FW_shoot_mg as 0 too, so the sum does not change. But n still counts these lines, so the mean drops. A mean that looks right does not mean that it is actually right. This is a good example to carefully think about what your code is doing since the code runs without any error but the output is still incorrect. In this case the difference is small, but depending on your data, such silent errors can have a large effect.

The means above have more decimals than the measurements. To round them, use printf instead of print. printf prints with a format that you choose: a piece of text with placeholders that the values fill in order. %d stands for a whole number and %.1f for a number with one decimal. \t is a tab and \n a new line. Everything else in the format, such as n: and mean:, is printed as it is:

awk -F'\t' '
  NR > 1 && $5 != "" { sum += $5; n++ }
  END                { printf "n: %d\tmean: %.1f\n", n, sum / n }
' awk_data/Growth_Data.txt

This prints:

n: 586  mean: 16.6

Unlike print, printf does not start a new line by itself, and it ignores OFS. Leave out the \n, and the prompt of your terminal ends up on the same line as the result. The tab between the values is there only because \t is in the format.

Count and mean per group: arrays

sum and n are single variables: each holds one value for the whole file. You can do more than that, for example count the plants per nutrient level. For this, you need one count per group. An array is a variable that holds one value per name. n["low_P"] is the count for low_P, and n["high_P"] the count for high_P. Just like a single variable, AWK makes the value for a new name the first time you use it, and it starts at 0.

awk -F'\t' '
  NR > 1 { n[$1]++ }
  END    { for (group in n) { print group, n[group] } }
' awk_data/Growth_Data.txt

This prints:

low_P 300
high_P 294

Taken apart:

  • NR > 1 { n[$1]++ }: for each row of data, add 1 to the count of its nutrient level. Piece by piece:

    • n is the name of the array.
    • [$1] picks one name in the array: the text in column 1. On a low_P row that is n["low_P"].
    • ++ adds 1 to the value under that name.

    So after the first low_P row, n["low_P"] is 1, after the second it is 2, and so on.

  • END { ... }: as before, this runs once, after the last line.

  • for (group in n) { print group, n[group] }: go through all names in n. For each name, put it into the variable group, and print the name and its count.

You can check the result with tools from the CLI workshop:

cut -f1 awk_data/Growth_Data.txt | sort | uniq -c

This prints:

      1 Nutrient
    294 high_P
    300 low_P

To calculate the mean per group, you do the same as for the whole file, but with two arrays: sum for the sum per group and n for the count per group. sum[$1] += $4 adds the root length to the sum of its group.

# Without the rule for empty fields
awk -F'\t' '
  NR > 1 { sum[$1] += $4; n[$1]++ }
  END    { for (group in sum) { print group, n[group], sum[group] / n[group] } }
' awk_data/Growth_Data.txt

# With the rule: skip empty root lengths
awk -F'\t' '
  NR > 1 && $4 != "" { sum[$1] += $4; n[$1]++ }
  END                { for (group in sum) { print group, n[group], sum[group] / n[group] } }
' awk_data/Growth_Data.txt

This prints:

low_P 300 57.9494
high_P 294 88.9501

low_P 290 59.9477
high_P 289 90.489

Without the rule, AWK adds 0 for each empty root length and still counts the plant. This is another silent error: both means come out too low, and nothing warns you.

Mean per nutrient and condition

To group data by more than one column, you can glue the columns together into one name: $1"-"$2 is column 1, a dash and column 2, for example low_P-mock. The dash goes in double quotes, because it is text here. A dash appears in none of the values, so you can split the name again later if you need to.

awk -F'\t' '
  NR > 1 && $4 != "" { group = $1"-"$2; sum[group] += $4; n[group]++ }
  END                { for (group in sum) { printf "%s\t%d\t%.1f\n", group, n[group], sum[group] / n[group] } }
' awk_data/Growth_Data.txt | sort

This prints:

high_P-129E 103 98.4
high_P-13C  85  97.7
high_P-mock 101 76.4
low_P-129E  99  69.9
low_P-13C   86  64.2
low_P-mock  105 47.1

Taken apart:

  • printf with the format "%s\t%d\t%.1f\n": the group name, a tab, the count as a whole number, a tab, and the mean with one decimal. %s is new: it stands for text, here the group name.
  • | sort: AWK goes through the names in an array in no fixed order. Sort the result, so that it is easy to read and to compare between runs.
ImportantForget the quotes, and the dash becomes a minus

If you write group = $1-$2 without the quotes, AWK reads the dash as a minus and subtracts column 2 from column 1. Text that does not start with a number counts as 0, so low_P and high_P both become 0, and 129E becomes 129. The command runs without an error, but prints this:

-129    202 84.4
-13 171 80.8
0   206 61.5

Three groups instead of six, and low_P and high_P plants mixed together. A quick check catches it: you expect 2 nutrient levels × 3 conditions = 6 groups, so count the lines of the output, and look at the group names.

Without the rule $4 != "", four of the six means are lower. For example, low_P with 129E gives 64.7 instead of 69.9, because the 8 plants without a root length count as 0 mm.

QuestionExercise
  1. Calculate the mean shoot weight per Condition, with one decimal. How many plants are in each group?
  2. Before you run it, predict: how many groups do you expect, and what should the counts add up to? Check the output against both numbers.
AnswerClick me to see an answer

Condition is column 2, and the shoot weight is column 5. Skip the empty shoot weights:

awk -F'\t' '
  NR > 1 && $5 != "" { sum[$2] += $5; n[$2]++ }
  END                { for (group in sum) { printf "%s\t%d\t%.1f\n", group, n[group], sum[group] / n[group] } }
' awk_data/Growth_Data.txt | sort

This prints:

129E    208 17.6
13C 173 15.3
mock    205 16.6

You expect 3 groups, one per condition. The counts should add up to the 594 plants minus the 8 without a shoot weight: 586, the same number as in the mean for the whole file. And 208 + 173 + 205 = 586. If the counts add up to more, the command did not skip the empty fields or the header.

What you learned

  • AWK can calculate with fields: print $0, $5 / $4 adds a new column. A command can stop halfway with an error and still leave a file, so count the lines after each step.
  • A long AWK command can be spread over several lines, one pattern and action per line. Keep the opening { on the same line as its pattern.
  • A variable (sum += $5) and END give a total or a mean for the whole file. An array (sum[$1] += $5) gives one per group.
  • printf prints with a format that you choose, for example %.1f for one decimal. It needs \n for a new line.
  • To group by two columns, glue them together with text in quotes: $1"-"$2. Without the quotes, the dash is a minus.
  • Skip empty fields before you calculate, and check that the counts add up to the number of rows you expect.
