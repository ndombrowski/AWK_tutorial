AWK on a table

On this page, you use AWK on a real table with plant growth measurements. You choose columns, keep the rows you need, add a new column, and calculate means per group. Along the way, you meet the most common trap when you work with tables: missing values that quietly change your results.

The same commands work on any table in plain text, and many bioinformatics tools write their results that way, for example BLAST, featureCounts or a GFF annotation file. With AWK you can filter or reshape such output right away, or pass it on to the next tool with a pipe, without saving it first or opening it in R. AWK never changes the file it reads: it prints the result on the screen, or into a new file if you ask for that.

The outputs on these pages come from a Linux computer (Ubuntu in WSL). On most computers you get the same result. Where this is not the case, the page says so.

Get the data: curl and tar

All example files for this tutorial come in one file, awk_data.tar.gz. A .tar.gz file packs many files into one and compresses them, similar to a .zip file.

# Go to your home folder, and make a folder for this tutorial
cd ~
mkdir awk_tutorial
cd awk_tutorial

# Download the data
# -L: if the link sends you on to another address, follow it
# -O: save the file under its own name, awk_data.tar.gz
curl -L -O "https://raw.githubusercontent.com/ndombrowski/AWK_tutorial/main/data/awk_data.tar.gz"

# Unpack it. Used options:
# -x extract, -z it is compressed (.gz), -f the file name follows
tar -xzf awk_data.tar.gz

# Check: you should see awk_data and awk_data.tar.gz
ls

# Check: you should see 14 files
ls awk_data
ls awk_data | wc -l

On this page you only need Growth_Data.txt. The other files are 16S sequences, a table with information on bacterial strains, and a second version of the growth table, which you use on later pages.

Look at the table first

Before you run any command on a table, you want to look at it first. You at leat want to know: how many lines it has, and what separates the columns?

# The first 5 lines
head -5 awk_data/Growth_Data.txt

# The number of lines
wc -l awk_data/Growth_Data.txt

This prints:

Nutrient    Condition   Experiment  Rootlength  FW_shoot_mg
low_P   mock    ex61    40.4    6.6
low_P   mock    ex61    38  6.8
low_P   mock    ex61    74.7    8.1
low_P   mock    ex61    34.4    8.3

595 awk_data/Growth_Data.txt

We see that the table has a header, a first line with the column names, and 594 rows of measurements. Each row is one plant and we have the following columns:

  • Nutrient: the plant grew with low or high phosphorus (low_P, high_P)
  • Condition: the plant was inoculated with nothing (mock) or with one of two bacteria (129E, 13C)
  • Experiment: the experiment the plant was part of (ex61, ex64, ex65)
  • Rootlength: root length in mm
  • FW_shoot_mg: shoot fresh weight in mg

The columns look like they are separated by spaces. However, you cannot see what is really there, because spaces and tabs look the same on screen. cat -A shows the invisible characters:

head -3 awk_data/Growth_Data.txt | cat -A

This prints:

Nutrient^ICondition^IExperiment^IRootlength^IFW_shoot_mg$
low_P^Imock^Iex61^I40.4^I6.6$
low_P^Imock^Iex61^I38^I6.8$

Here, ^I is a tab, and $ marks the end of each line. So this tells us that we work with a tab-separated table. You need to know this for the next steps.

TipTip: cat -A on a Mac (optional)

On a Mac, cat -A may not work. cat -et shows the same: tabs as ^I and line ends as $.

The shape of an AWK command

Every AWK command on this page has the same shape:

awk -F'\t' 'pattern { action }' file
  • -F'\t' tells AWK that the columns are separated by tabs. -F stands for field separator. A field is one value in a line, like one cell in a spreadsheet row.
  • 'pattern { action }' is the AWK program, it always needs to be between single quotes. The pattern says which lines to work on. The action, between curly brackets, says what to do with them.
  • file is the file AWK reads.

AWK reads the file one line at a time. For each line, it checks the pattern. If the line matches, AWK runs the action. You can leave out either part: without a pattern, the action runs on every line. Without an action, AWK prints the lines that match.

print: choose columns

AWK gives each field of a line a number: $1 is the first field, $2 the second, and so on. $0 is the whole line. To print the first column:

# Print column 1 of every line, and show the first 3 lines of the result
awk -F'\t' '{ print $1 }' awk_data/Growth_Data.txt | head -3

This prints:

Nutrient
low_P
low_P

To print several columns, separate the fields you want with a comma:

# Print column 1 (Nutrient) and column 4 (Rootlength)
awk -F'\t' '{ print $1, $4 }' awk_data/Growth_Data.txt | head -3

This prints:

Nutrient Rootlength
low_P 40.4
low_P 38

AWK puts a space between the printed columns. To keep the result a tab-separated table, tell AWK to use a tab in the output too. -v OFS='\t' sets the output field separator:

awk -F'\t' -v OFS='\t' '{ print $1, $4 }' awk_data/Growth_Data.txt | head -3

This prints:

Nutrient    Rootlength
low_P   40.4
low_P   38

You can do the same thing with cut -f1,4 (something you might have seen in our CLI workshop). AWK becomes more useful in the next sections, where you choose rows too.

A quick check for any table is to count the fields in each line. NF is the number of fields in the current line:

# Count the fields per line, then count how often each number occurs
awk -F'\t' '{ print NF }' awk_data/Growth_Data.txt | sort | uniq -c

This prints:

    595 5

This tells us that all 595 lines have 5 fields. If some lines had 4 or 6, something in the table would be off and together this gives us a quick command to check that our data has the right structure.

NR: the header line

NR is the number of the record, the line AWK is reading now. You use it in a pattern to choose lines by their position:

# Only line 1, the header
awk -F'\t' 'NR == 1' awk_data/Growth_Data.txt

# All lines after the header: show the first 2, and count them
awk -F'\t' 'NR > 1' awk_data/Growth_Data.txt | head -2
awk -F'\t' 'NR > 1' awk_data/Growth_Data.txt | wc -l

This prints:

Nutrient    Condition   Experiment  Rootlength  FW_shoot_mg
low_P   mock    ex61    40.4    6.6
low_P   mock    ex61    38  6.8
594

These commands have only a pattern and no action, so AWK prints the lines that match. NR > 1 skips the header and keeps all 594 rows of data. You need it often, as the next sections show.

Subset rows by text

To keep only the rows of the plants grown with low phosphorus, compare column 1 with the text low_P:

awk -F'\t' '$1 == "low_P"' awk_data/Growth_Data.txt | head -3
awk -F'\t' '$1 == "low_P"' awk_data/Growth_Data.txt | wc -l

This prints:

low_P   mock    ex61    40.4    6.6
low_P   mock    ex61    38  6.8
low_P   mock    ex61    74.7    8.1

300

Two details matter here:

  • Text goes between double quotes: "low_P". Without quotes, AWK reads low_P as the name of a variable, a named box that holds a value. That box is empty, so no row matches.
  • To compare, use two equal signs: ==. If you would use only one equal sign this command would do something else and instead put a value into a field. Note here, how AWK gives you no error message and only by inspecting the output we will see that the command is doing something different to what we wanted:
# Wrong: one = instead of two
awk -F'\t' '$1 = "low_P"' awk_data/Growth_Data.txt | head -3
awk -F'\t' '$1 = "low_P"' awk_data/Growth_Data.txt | wc -l

This prints:

low_P Condition Experiment Rootlength FW_shoot_mg
low_P mock ex61 40.4 6.6
low_P mock ex61 38 6.8

595

Here, every line is kept, but column 1 of every line now says low_P, even in the header, and the tabs became spaces. A quick wc -l shows the problem: 595 lines, the same as the whole file.

Why not use grep?

If you have followed the CLI workshop you might remember grep, which keeps lines that contain a word. For the plants with bacterium 13C, both tools give the same count:

grep '13C' awk_data/Growth_Data.txt | wc -l
awk -F'\t' '$2 == "13C"' awk_data/Growth_Data.txt | wc -l

This prints:

175
175

But there is an important difference: grep searches the whole line, not one column. If you search for 13 and you get more lines:

grep '13' awk_data/Growth_Data.txt | wc -l
grep '13' awk_data/Growth_Data.txt | head -3

This prints:

211

low_P   mock    ex61    55.3    13.3
low_P   mock    ex61    48.7    13.9
low_P   mock    ex64    46.93   13.52

In total this command gives us 36 extra lines, because 13 also appears in shoot weights such as 13.3. The first lines grep finds are not even 13C plants, but mock plants with such a shoot weight. In contrast, AWK compares only column 2, so this cannot happen making this a much safer command.

Keep rows by number

Comparisons also work with numbers: > (greater than), < (less than), >= and <= (greater or less than, or equal). To keep plants with roots longer than 50 mm:

awk -F'\t' '$4 > 50' awk_data/Growth_Data.txt | head -3
awk -F'\t' '$4 > 50' awk_data/Growth_Data.txt | wc -l

This prints:

Nutrient    Condition   Experiment  Rootlength  FW_shoot_mg
low_P   mock    ex61    74.7    8.1
low_P   mock    ex61    66.5    8.9

476

Important: Note how the header is in the result? Column 4 of the header is the word Rootlength, not a number. When a value is not a number, AWK compares it as text, and in that comparison Rootlength counts as larger than 50. To avoid this we need to add NR > 1 to skip the header. To combine patterns we can use &&, which means “and”: both conditions must be true.

awk -F'\t' 'NR > 1 && $4 > 50' awk_data/Growth_Data.txt | wc -l

This prints:

475

|| means “or”: We can use this if we want at least one of the conditions to be true.

# Low phosphorus and no bacteria
awk -F'\t' '$1 == "low_P" && $2 == "mock"' awk_data/Growth_Data.txt

# Either of the two bacteria
awk -F'\t' '$2 == "129E" || $2 == "13C"' awk_data/Growth_Data.txt

Missing values: empty fields

Now look for plants with very short roots, below 10 mm:

awk -F'\t' 'NR > 1 && $4 < 10' awk_data/Growth_Data.txt | wc -l
awk -F'\t' 'NR > 1 && $4 < 10' awk_data/Growth_Data.txt | head -3

This prints:

15

high_P  mock    ex61        18.2
high_P  mock    ex64        22.4
high_P  mock    ex64        26

15 plants, but if we look at the table we notice that none of them has a root length below 10. Instead you will notice that these rows have no root length at all. If we use cat -A this will show us exactly what is in the file for these fields:

awk -F'\t' 'NR > 1 && $4 < 10' awk_data/Growth_Data.txt | head -3 | cat -A

This prints:

high_P^Imock^Iex61^I^I18.2$
high_P^Imock^Iex64^I^I22.4$
high_P^Imock^Iex64^I^I26$

We see two tabs side by side, ^I^I, with nothing between them: this is an empty field and also how a missing value often looks, for example in a table saved from Excel with empty cells. Count them per column:

# Empty root length (column 4) and empty shoot weight (column 5)
awk -F'\t' '$4 == ""' awk_data/Growth_Data.txt | wc -l
awk -F'\t' '$5 == ""' awk_data/Growth_Data.txt | wc -l

This prints:

15
8

Altogether, this tells us that AWK did not give an error but it did something we didn’t really want. It compared the empty field with 10 as text, and empty text counts as smaller than anything. So all 15 plants without a root length passed the filter $4 < 10. In calculations, AWK will treat an empty field as 0, as you see further down.

ImportantImportant: skip empty fields before you compare or calculate

Before you compare or calculate with a column, keep only the rows that have a value in it, with $4 != "". != means “is not equal to”, and "" is empty text, so $4 != "" means “column 4 is not empty”:

awk -F'\t' 'NR > 1 && $4 != "" && $4 < 10' awk_data/Growth_Data.txt | wc -l

This prints:

0

No plant in this table has roots shorter than 10 mm.

Why -F'\t' matters

AWK can also run without -F'\t'. It then splits lines at any run of spaces and tabs. For most lines in this table, the result is the same. But AWK then treats the two tabs around an empty field as one separator, and the values move one column to the left. Line 123 is the first row with an empty root length:

# Line 123, and its column 4 with -F'\t'
awk -F'\t' 'NR == 123' awk_data/Growth_Data.txt
awk -F'\t' 'NR == 123 { print $4 }' awk_data/Growth_Data.txt

# Column 4 of the same line without -F'\t'
awk 'NR == 123 { print $4 }' awk_data/Growth_Data.txt

# Number of fields per line without -F'\t'
awk '{ print NF }' awk_data/Growth_Data.txt | sort | uniq -c

This prints:

high_P  mock    ex61        18.2

18.2

     23 4
    572 5

With -F'\t', column 4 of line 123 is empty (the empty line in the output). Without it, column 4 is 18.2, the shoot weight. The 23 lines with an empty field now have only 4 fields. Again there is no error. The NF check from above shows the problem right away, so it is worth running on every new table.

TipTip: fill empty fields with NA (optional)

Empty fields are easy to miss. One way to make them visible is to fill each empty field with NA (not available) and save the result as a new file. In this table, only column 4 and column 5 have empty fields, so you fill those two:

# If column 4 is empty, put NA into it.
# If column 5 is empty, put NA into it.
# Then print every line.
# The command is spread over several lines to make it easier to read
# (more on this in "Add a column" below).
awk -F'\t' -v OFS='\t' '
  $4 == "" { $4 = "NA" }
  $5 == "" { $5 = "NA" }
  { print }
' awk_data/Growth_Data.txt > Growth_Data_NA.txt

# Check: same number of lines, and line 123 now has NA
wc -l Growth_Data_NA.txt
awk -F'\t' 'NR == 123' Growth_Data_NA.txt

This prints:

595 Growth_Data_NA.txt
high_P  mock    ex61    NA  18.2

Also here -v OFS='\t' matters. When you change a field, AWK rebuilds the whole line and puts the output separator between the fields. Without -v OFS='\t', that is a space. Only the changed lines get spaces, the others keep their tabs, so the file now mixes both. cat -A shows this for line 123 (changed) and line 2 (not changed) of such a file:

high_P mock ex61 NA 18.2$
low_P^Imock^Iex61^I40.4^I6.6$

If you do not know which columns have empty fields, or there are many columns, you can let AWK go through all fields with a loop. You do not need to remember this form. Keep it in your notes, or ask an LLM for it and check the result as shown here. In this table it gives exactly the same file:

# For each field in the line (i = 1 up to the number of fields NF):
# if the field is empty, put NA into it. Then print the line.
awk -F'\t' -v OFS='\t' '
  {
    for (i = 1; i <= NF; i++) {
      if ($i == "") { $i = "NA" }
    }
    print
  }
' awk_data/Growth_Data.txt

Now the missing values are visible when you look at the file. Also, the columns no longer shift in tools that split at spaces and tabs, such as AWK without -F'\t', or join and column -t with their default settings.

But when you do this, it’s important to know that NA does not make comparisons safe. NA is text too, and in a text comparison it counts as larger than 50:

awk -F'\t' 'NR > 1 && $4 > 50' Growth_Data_NA.txt | wc -l
awk -F'\t' 'NR > 1 && $4 != "NA" && $4 > 50' Growth_Data_NA.txt | wc -l

This prints:

490
475

So with NA, the rule stays the same, only with $4 != "NA" instead of $4 != "".

Add a column

AWK can calculate with fields. For example, the shoot weight per mm of root is $5 / $4. To add it as a new column at the end of each line, print the whole line $0 and then the result:

awk -F'\t' -v OFS='\t' 'NR > 1 { print $0, $5 / $4 }' awk_data/Growth_Data.txt > shoot_per_root.txt

wc -l shoot_per_root.txt

This prints:

awk: cmd. line:1: (FILENAME=awk_data/Growth_Data.txt FNR=123) fatal: division by zero attempted
121 shoot_per_root.txt

The error message tells us that AWK stopped at line 123: the first row with an empty root length. That is because it treated the empty field as 0, and a division by 0 is not possible. The file shoot_per_root.txt still exists, but it has only 121 lines instead of 594. If you missed the error message and only looked at head, the file would look fine. This is why you want to make it a habit to count lines after each step.

To fix this, you need to skip rows with an empty root length or shoot weight, and print a header for the new column. The command now has two parts, each with its own pattern and action.

A command with several parts gets long on one line. AWK lets you spread the part between the single quotes over several lines, so you can put each pattern and its action on a line of its own. The command does exactly the same, it is only easier to read. You can copy it into your terminal as it is: the terminal waits for the closing quote before it runs the command.

# Part 1: on line 1, print the current header and add a name for the new column
# Part 2: on the other lines with both values, print the line plus the result
awk -F'\t' -v OFS='\t' '
  NR == 1                          { print $0, "shoot_per_root" }
  NR > 1 && $4 != "" && $5 != ""   { print $0, $5 / $4 }
' awk_data/Growth_Data.txt > shoot_per_root.txt

# Check the result
head -3 shoot_per_root.txt
wc -l shoot_per_root.txt

This prints:

Nutrient    Condition   Experiment  Rootlength  FW_shoot_mg shoot_per_root
low_P   mock    ex61    40.4    6.6 0.163366
low_P   mock    ex61    38  6.8 0.178947

572 shoot_per_root.txt

572 lines: the header plus 571 plants. Does that add up? 594 plants, minus 15 without a root length, minus 8 without a shoot weight, is 571. No plant misses both values, so no row is subtracted twice.

ImportantKeep the opening brace on the same line as its pattern

When you spread a command over several lines, the opening { of an action must stay on the same line as its pattern. If you move the { to the next line, AWK reads the pattern on its own (which prints every matching line) and the action on its own (which runs on every line). You get no error, only a different result.

Sum and mean of a column: variables and END

You will notice that the commands from here on are longer than the ones before. You could do the same thing in R or Python, and you might wonder why even learn them in AWK? The reason is that in bioinformatics you often only need a quick look at your data: how many plants are in each group, and do the means look sensible? AWK gives you that answer in the terminal, without starting another program or loading the table first. On a computer cluster, where R or Python may not be set up for you, AWK is always there. And because AWK reads a file one line at a time, it also works on files that are too large to open comfortably in R or Excel. For statistics and plots, R or Python remain the better tools. AWK is for the quick check before, or for cleaning up a table before you load it there.

Start with one number: the total shoot weight of all plants. For this, AWK needs a variable, a named box that holds a value. You do not need to create it first: AWK makes the box the first time you use it, and it starts at 0.

awk -F'\t' 'NR > 1 && $5 != "" { sum += $5 } END { print sum }' awk_data/Growth_Data.txt

This prints:

9715.23

Taken apart:

  • sum += $5: add the shoot weight of this line to the box sum. += means “add to what is already in the box”.
  • END { print sum }: END is a special pattern. Its action runs once, after AWK has read the last line. By then, sum holds the total.

The name sum is your own choice. You could call it total or weight instead, and get the same result. Names such as NR, NF and END are different: they belong to AWK and have a fixed meaning.

For the mean, you need a second box that counts the plants. Here it is called n (short for “number of plants”), and n++ adds 1 to it. The ; separates two steps inside one action:

awk -F'\t' '
  NR > 1 && $5 != "" { sum += $5; n++ }
  END                { print n, sum, sum / n }
' awk_data/Growth_Data.txt

This prints the number of plants, the total and the mean:

586 9715.23 16.5789

Does 586 add up? 594 plants, minus the 8 without a shoot weight, is 586.

Now leave out the rule for empty fields, and then also NR > 1:

# Without $5 != ""
awk -F'\t' '
  NR > 1 { sum += $5; n++ }
  END    { print n, sum, sum / n }
' awk_data/Growth_Data.txt

# Also without NR > 1
awk -F'\t' '
  { sum += $5; n++ }
  END { print n, sum, sum / n }
' awk_data/Growth_Data.txt

This prints:

594 9715.23 16.3556

595 9715.23 16.3281

The total is the same all three times. AWK adds an empty field as 0, and the header text FW_shoot_mg as 0 too, so the sum does not change. But n still counts these lines, so the mean drops. A total that looks right does not mean that the mean is right. Look at the count as well: you expect 586.

Count and mean per group: arrays

sum and n are single boxes: each holds one value for the whole file. To count the plants per nutrient level, you need one box per group. A set of named boxes like this is called an array. n["low_P"] is the box for low_P, n["high_P"] the box for high_P. Just like a variable, AWK makes each box the first time you use it, and it starts at 0.

awk -F'\t' '
  NR > 1 { n[$1]++ }
  END    { for (group in n) { print group, n[group] } }
' awk_data/Growth_Data.txt

This prints:

low_P 300

high_P 294

Taken apart:

  • NR > 1 { n[$1]++ }: for each row of data, add 1 to the box of its nutrient level. Piece by piece:
    • n is the name of the array, the set of boxes.
    • [$1] picks one box: the box named after the value in column 1. On a low_P row that is n["low_P"].
    • ++ adds 1 to that box.
    So after the first low_P row, n["low_P"] is 1, after the second it is 2, and so on.
  • END { ... }: as before, this runs once, after the last line.
  • for (group in n) { print group, n[group] }: go through all boxes in n. For each box, put its name into group, and print the name and the count.

You can check the result with tools from the CLI workshop:

cut -f1 awk_data/Growth_Data.txt | sort | uniq -c

This prints:

      1 Nutrient
    294 high_P
    300 low_P

For a mean per group, you do the same as for the whole file, but with one sum box and one n box per group. sum[$1] += $4 adds the root length to the sum of its group.

# Without the rule for empty fields
awk -F'\t' '
  NR > 1 { sum[$1] += $4; n[$1]++ }
  END    { for (group in sum) { print group, n[group], sum[group] / n[group] } }
' awk_data/Growth_Data.txt

# With the rule: skip empty root lengths
awk -F'\t' '
  NR > 1 && $4 != "" { sum[$1] += $4; n[$1]++ }
  END                { for (group in sum) { print group, n[group], sum[group] / n[group] } }
' awk_data/Growth_Data.txt

This prints:

low_P 300 57.9494
high_P 294 88.9501

low_P 290 59.9477
high_P 289 90.489

Without the rule, AWK adds 0 for each empty root length and still counts the plant. Both means come out too low, and nothing warns you.

Mean per nutrient and condition

To group by two columns, glue them together into one box name: $1"-"$2 is column 1, a dash and column 2, for example low_P-mock. The dash goes in double quotes, because it is text here. A dash appears in none of the values, so you can split the name again later if you need to.

awk -F'\t' '
  NR > 1 && $4 != "" { group = $1"-"$2; sum[group] += $4; n[group]++ }
  END                { for (group in sum) { printf "%s\t%d\t%.1f\n", group, n[group], sum[group] / n[group] } }
' awk_data/Growth_Data.txt | sort

This prints:

high_P-129E 103 98.4
high_P-13C  85  97.7
high_P-mock 101 76.4
low_P-129E  99  69.9
low_P-13C   86  64.2
low_P-mock  105 47.1

Two new parts:

  • printf prints with a format that you choose. %s stands for text, %d for a whole number, %.1f for a number with one decimal, \t for a tab and \n for a new line. The values after the format fill these places in order.
  • | sort: AWK goes through the boxes in no fixed order. Sort the result, so that it is easy to read and to compare between runs.
ImportantForget the quotes, and the dash becomes a minus

If you write group = $1-$2 without the quotes, AWK reads the dash as a minus and subtracts column 2 from column 1. Text that does not start with a number counts as 0, so low_P and high_P both become 0, and 129E becomes 129. The command runs without an error, but prints this:

-129    202 84.4
-13 171 80.8
0   206 61.5

Three groups instead of six, and low_P and high_P plants mixed together. A quick check catches it: you expect 2 nutrient levels × 3 conditions = 6 groups, so count the lines of the output, and look at the group names.

Without the rule $4 != "", four of the six means are lower. For example, low_P with 129E gives 64.7 instead of 69.9, because the 8 plants without a root length count as 0 mm.

Condition is column 2, and the shoot weight is column 5. Skip the empty shoot weights:

awk -F'\t' '
  NR > 1 && $5 != "" { sum[$2] += $5; n[$2]++ }
  END                { for (group in sum) { printf "%s\t%d\t%.1f\n", group, n[group], sum[group] / n[group] } }
' awk_data/Growth_Data.txt | sort

This prints:

129E    208 17.6
13C 173 15.3
mock    205 16.6

What you learned

  • An AWK command has the shape awk -F'\t' 'pattern { action }' file.
  • $1, $2, … are the fields of a line, $0 the whole line, NF the number of fields, NR the line number.
  • Compare with ==, !=, >, <, and combine with && (and) and || (or). Text goes in double quotes.
  • A variable (sum += $5) and END give a total or a mean for the whole file; an array (sum[$1] += $5) gives one per group.
  • Look at the table first: cat -A for tabs and empty fields, NF for the number of fields per line.
  • Empty fields cause errors without a warning: skip them with $4 != "" before you compare or calculate.
  • After each step, check the result: count the lines, and look at it with head.

You do not need to learn these commands by heart. Instead, keep your own notes: a text file or notebook with the commands you have checked, each with one line on what it does and which trap it avoids (for example “skips empty fields in column 4”). A checked command in your notes is worth more than one you half remember, and more than a new one from an LLM that you still have to check.
